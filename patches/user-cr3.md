- **Grund:** ZehOS N1-B3 (#632): ein Thread läuft auf einer `UserPageTable`. `BindToCurrentThread` bindet den Thread und lädt die Tabelle sofort; jeder Wechsel lädt unter der Queue-Sperre der CPU (`SwitchFor` in `ScheduleFromInterruptLocked` und `Schedule`) die Tabelle des nächsten Threads oder die Kernelwurzel der CPU, bevor die CPU den Stapel des alten Threads verlässt. Die Bindung endet mit `UnbindCurrentThread`, in `ExitThread` (eigener Thread: lösen und Kernelwurzel laden; fremder, etwa ein gekillter wartender: nur lösen) und beim Wechsel weg von einem toten Thread (an einem Fehler aufgegeben, laufend gekillt). Ohne TLB-Shootdown (erst N4, Option B): `TryProtect` gibt false und `Unmap` 0 zurück, ohne etwas zu ändern, solange eine andere CPU auf der Tabelle läuft; geprüft wird vor und nach dem Schreiben, bei einem Wechsel dazwischen wird der alte Eintrag zurückgeschrieben. Auf der eigenen CPU folgt `invlpg`. `Dispose` wirft `InvalidOperationException`, solange ein Thread gebunden ist, und wartet auf CPUs, die die Tabelle noch in CR3 halten. `EfiRtc.TryGetTime` gibt unter einer fremden Tabelle false zurück, ohne die Firmware aufzurufen (sie folgt der Identitätsabbildung).
- **Entfernter ZehOS-Umweg:** keiner
- **Grenzen:** kein Shootdown; bis N4 sind alle Threads eines Prozesses an eine CPU gebunden, das prüft dieser Patch nicht. Kein PCID: jeder Wechsel zwischen Tabellen leert den TLB der unteren Hälfte. Ein laufend gekillter Thread behält wie ohne Patch seinen Platz (`MarkedForExit`), seine Bindung endet trotzdem beim Wechsel. ARM64 hat keine Tabellen (`TryCreate` null, Zellen übersprungen). Die EfiRtc-Sperre ist nur gelesen, nicht im Gast ausgelöst: der einzige Aufrufer läuft beim Start, vor jeder Bindung, und der Testkern kommt nicht an die interne Klasse.
