# fat-rename-open

- **Commit:** nach Merge einzutragen; geschrieben auf `origin/cosmos` 6b28fc44
- **Dateien:** `src/Cosmos.Kernel.System/FileSystem/Fat/FatSuperblock.cs`, `FatInodeOperations.cs` (`Rename`), `FileSystem/VfsManager.Paths.cs` (`TryRename`, `DropDisplacedEntry`); Tests `tests/Cosmos.Kernel.Tests.System/FileSystem/Fat/FatOpenHandleTests.cs`, `VfsRenameOpenTests.cs`
- **Grund:** Datenverlust (ZehOS #702). `Rename` legte unter FAT für den Zieleintrag ein neues Inode an und ersetzte damit das lebende im Cache; das Inode der offenen Handle behielt seinen alten Verzeichnisplatz. `Release` schreibt immer (`Fsync`), auch bei einem reinen Leser: Das Schließen trug Cluster und Größe der alten Datei in den Eintrag ein, der den Platz inzwischen belegt. Leere Dateien waren gar nicht auffindbar (kein Startcluster). Zusätzlich behielt eine Handle beim Umbenennen `OpenedPath` (VFS, auch ext2): Löschen einer neuen Datei unter dem alten Namen wurde aufgeschoben und traf beim Schließen eine spätere Datei dieses Namens
- **Änderung:** `Rename` zieht das lebende Inode mit (Name, Elternverzeichnis, Platz). Inodes ohne Startcluster sind über (Startcluster des Elternverzeichnisses, Platz) schwach auffindbar. `RemoveDirectoryEntry` vergleicht auch das Elternverzeichnis. Beim Kürzen auf 0 wird der freigegebene Cluster aus dem Cache genommen. `TryRename` führt `OpenedPath` und `PendingUnlinkPath` offener Handles der umbenannten Datei nach; eine ersetzte, noch offene Datei zeigt danach auf ihren Sicherungsnamen
- **Entfernter ZehOS-Umweg:** keiner
- **Grenzen:** Nur Dateien: Wird ein Verzeichnis umbenannt, behalten Handles darin im VFS den alten Pfad (Inode und Platz stimmen). `MarkPendingIfOpen` und `DropDisplacedEntry` vergleichen Pfade weiter ohne Groß- und Kleinschreibung, auch auf ext2 (Vorbestand). Wird eine zum Löschen vorgemerkte Datei unter demselben Namen mit `FileMode.Create` geöffnet, trifft das Löschen den neuen Inhalt (Vorbestand, nicht geprüft). Keine eigene Sperre; Operationen serialisiert der Aufrufer (ZehOS: `StorageLock`). Zeilenkonflikte mit `fat-inode-cache` (#703) in `FatSuperblock.cs` möglich
