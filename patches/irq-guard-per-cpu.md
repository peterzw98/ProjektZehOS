# irq-guard-per-cpu

- **Commit:** Squash des PRs gegen `cosmos`
- **Dateien:** `src/Cosmos.Kernel.HAL/DriverKit/Engine/InterruptContextGuard.cs`, `src/Cosmos.Kernel.HAL/Cosmos.Kernel.HAL.csproj` (`InternalsVisibleTo` für die Smp-Suite), `tests/Kernels/Cosmos.Kernel.Tests.Smp/Kernel.cs` (Zelle `InterruptGuard_HandlerOnOtherCpu_NotSeenHere`, 42 Tests je Zelle), `docs/articles/dev/testing.md`
- **Grund:** `InterruptContextGuard` führte Tiefe und Synthetik-Flag als je ein statisches Wort für alle CPUs („Single CPU today … to become per-CPU“). Unter SMP sah jeder Thread auf CPU n einen Treiber-Interrupt-Handler auf CPU 0 als eigenen: Ein Thread-Kontext-Member (`Delay`, `ControlTransfer`, `Publish` …) hielt mit `Panic.Halt(<Member>)` das System an (ZehOS E5-D, Desktop unter `-smp 4`, `Panic.Halt("Delay")`), in einer synthetischen Dispatch warf er. Jetzt hat jede CPU einen Slot (Tiefe, Synthetik) in einem statischen `[InlineArray(PerCpuBlock.MaxCpus)]`: keine Allokation, kein statischer Konstruktor, der erste `Enter` darf aus einem echten Interrupt kommen; nur die CPU selbst schreibt ihren Slot, mit gesperrten Interrupts. `IsInHandler` und `ThrowIfInHandler` lesen Index und Slot unter `InternalCpu.DisableInterruptsScope()`, sonst könnte ein Thread zwischen Index und Slot auf eine andere CPU wandern und deren Slot lesen. ZehOS-Plan `2026-11-18-multicore-e5-smp.md`, E5-L (#498), Blocker für E5-J
- **Grenzen:** Ein verschachtelter `Enter` überschreibt das Synthetik-Flag des äußeren, und `Exit` stellt es nicht wieder her (wie vor dem Patch, jetzt je CPU). Ein Handler, der selbst Interrupts freigibt und dabei verschoben wird, ließe seinen Slot auf der alten CPU stehen; Handler laufen maskiert, das bleibt Vertrag.
- **Entfernter ZehOS-Umweg:** keiner (es gab keinen; ZehOS-Desktop unter SMP hielt sporadisch an)
- **Prüfung:** Smp-Suite (`Cosmos.TestRunner.Engine`, `tests/Kernels/Cosmos.Kernel.Tests.Smp`, x64, Zellen `bare` und `bare+smp4`): ohne Fix rot, mit Fix 42/42 je Zelle; ZehOS: nativer Bau mit gepinntem Stand, Desktop unter `ZEHOS_QEMU_SMP=4` (KVM) mindestens 5/5 ohne `Panic.Halt`
