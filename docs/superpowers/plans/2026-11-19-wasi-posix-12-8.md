# Roadmap 12.8 (P4): Dateien und POSIX-Breite für Pakete

> **Für ausführende Agenten:** Empfohlene Arbeitsweise superpowers:executing-plans. Schritte haben Kästchen zum Abhaken.
> Board-Block #419. Lead: agent-nweh-lead1 (Team peter). Planfragen an den Lead im Kanal `#second`.

**Ziel:** Die C-Tests aus [wasi-testsuite](https://github.com/WebAssembly/wasi-testsuite) (Apache-2.0, gegen wasi-libc übersetzt) laufen unverändert
als Paket, soweit sie nur das Paket lesen, `/save` nutzen und Uhren brauchen: Paketverzeichnisse lesen, `poll_oneoff` mit Uhren, Uhren und Zeitstempel,
fehlende Preview-1-Imports. Schreiben bleibt auf `/save` (13.4) beschränkt.

**Abweichung von der Quelle:** [Plan Roadmap 12](2026-11-17-roadmap-12.md), Zeile 26, nennt „ein unverändertes POSIX-Testprogramm aus wasi-libc“ und
`/data`. Die Tests im Repository von wasi-libc prüfen die Bibliothek selbst; wasi-testsuite ist die übliche Konformitätsprobe für Preview 1 und wird
mit wasi-libc gebaut. Aus Sicht der App heißt `/data/.zehos-apps/<paket>/<konto>` `/save` (`docs/PAKETE_ERSTELLEN.md:145`). Die „Rechte aus 6c“ sind
`capability=storage` (`ProjektZeh/Packages/PackageManifest.cs:61`); daran ändert sich nichts.

**Architektur:** Alle WASI-Imports stehen in einer Tabelle (`ProjektZeh/Native/Wasm/host/zehos_host_core.h:62-118`) und werden von wasm3
(`zehos_host_wasm3.c`) und WAMR-AOT (`zehos_host_wamr.c:140-185`, WAMR ohne eigene WASI: `ProjektZeh/ProjektZeh.csproj:73`) gemeinsam genutzt.
Dateizugriffe beantwortet C# über `zehos_wasm_host_*`-Rückrufe (`ProjektZeh/Runtime/Wasm/WasmRuntime.HostCallbacks.cs`, `WasmSaveStore.cs`).
Hostaufrufe laufen synchron auf dem Wasm-Worker, nie in der Hauptschleife (`WasmRuntime.cs:21-38`).

**Testaufbau, den alle Pakete kennen müssen:** `WasmRuntime.cs` steht unter `#if ZEHOS_WASM` (Zeile 1) und gehört **nicht** zum Hostbuild;
`ProjektZeh.Tests` bindet nur `WasmRuntime.HostCallbacks.cs` ein. Die nativen Tests (`scripts/tests/test_wasm_input_native.py:152`) linken den
echten C-Kern mit wasm3 und Stubs aus `scripts/tests/wasm-input-host.c` (Zeilen 8-102). **Jeder neue oder geänderte `zehos_wasm_host_*`-Rückruf
braucht dort einen Stub**, sonst bricht das Linken.

## Feste Werte

| Name | Wert |
| --- | --- |
| Schlaf in `poll_oneoff` | Schleife in C: `zehos_wasm_host_sleep_ms(min(10, Rest))`, danach `zehos_wasm_host_should_exit()`; **keine** Obergrenze für die Gesamtdauer (wasi-libc ruft `poll_oneoff` für `nanosleep` einmal auf und prüft `nevents` nicht). Bei `should_exit` kehrt der Aufruf mit 0 Ereignissen zurück |
| Höchstzahl Abos je `poll_oneoff` | 64; 0 oder mehr → `EINVAL` |
| Uhren in `poll_oneoff` | IDs 0–3 wie `clock_time_get`; andere → Ereignis mit `EINVAL` |
| fd-Abos | offene Datei-fds und fd 1/2 sofort bereit (`nbytes` = Restlänge bzw. 0); fd 0, Ordner-fds, unbekannte fds → Ereignis mit `EBADF` |
| `clock_res_get` | Uhr 0: 1 ms; 1–3: Auflösung der Stopwatch in ns (neuer Rückruf, mindestens 1); andere IDs `EINVAL` |
| `filestat` | `dev` = 1 (Paket) bzw. 2 (`/save`); `ino` = FNV-1a-64 des normierten Pfads relativ zur Wurzel; `atim = mtim = ctim` = letzte Änderungszeit in ns (UTC), unbekannt 0 |
| `fd_renumber` | `fd == to` → Erfolg ohne Wirkung; nur Datei- und Ordner-fds ab 5, sonst `EBADF`; Fehler beim Schließen des Ziels wird zurückgegeben, Quelle bleibt |
| `fd_allocate` | `ENOTSUP`; `proc_raise`: `ENOSYS`; `fd_datasync` = `fd_sync` |
| Tabellen-Signaturen (Ergebnis `i`) | `fd_renumber` `"ii"`, `fd_datasync` `"i"`, `fd_allocate` `"iII"`, `proc_raise` `"i"`, `poll_oneoff` `"**i*"` (heute schon so); `zehos_host_wamr.c` macht daraus `"(…)i"` |
| Längste Pfadlänge | 255 Bytes für den **zusammengesetzten** Pfad (Ordner + Name); darüber `ENAMETOOLONG` |

## Review-Schwerpunkte

1. Jeder Gastzeiger und jede Länge in `poll_oneoff` überlaufsicher geprüft, `nsubscriptions * 48` und `* 32` ohne Überlauf (Layout: Abo 48 Byte, Ereignis 32 Byte).
2. Paketordner: kein Ausbruch aus `package.FilesDirectory` über `..`, Symlinks oder ReparsePoints **in jeder Pfadkomponente**. `Resolve`
   (`WasmPackagePaths.cs:18-25`) prüft heute nur die letzte Komponente (`:36`); P4-A prüft alle und nimmt dafür einen Test auf.
3. Jede Stelle, die heute nur `ZEHOS_FILE_SAVE_DIRECTORY` abfragt, kennt die neue Art (P4-B, Liste dort); Schließen eines Paketordners geht nie an `save_close`.
4. `poll_oneoff` blockiert nie die Hauptschleife und endet spätestens 10 ms nach `should_exit`.
5. Keine Ausnahme überquert `UnmanagedCallersOnly`; neue Rückrufe fangen wie die vorhandenen.

### Paket P4-A: Paketordner (C#)

**Branch:** `task/p4-a-paketordner` von `master`.

**Schnittstellen** (`WasmRuntime.HostCallbacks.cs`, Muster `HostOpen` `:22-44`, unter `StorageLock`, Rückgabe WASI-Errno). Ein Ordner-Handle merkt sich
in C# seinen Pfad relativ zur Wurzel; C speichert nur das Handle.

```csharp
[UnmanagedCallersOnly(EntryPoint = "zehos_wasm_host_package_opendir")]   // dirHandle -1 = Paketwurzel
static int HostPackageOpenDir(int dirHandle, byte* path, uint length, int* handle);
[UnmanagedCallersOnly(EntryPoint = "zehos_wasm_host_package_readdir")]
static int HostPackageReadDir(int handle, byte* buffer, uint length, ulong cookie, uint* used);
[UnmanagedCallersOnly(EntryPoint = "zehos_wasm_host_package_closedir")]
static void HostPackageCloseDir(int handle);
[UnmanagedCallersOnly(EntryPoint = "zehos_wasm_host_package_openat")]    // Datei relativ zu einem Ordner-Handle, lesend
static int HostPackageOpenAt(int dirHandle, byte* path, uint length, int* handle, ulong* size);
[UnmanagedCallersOnly(EntryPoint = "zehos_wasm_host_package_statat")]    // Typ und Größe relativ zu einem Ordner-Handle
static int HostPackageStatAt(int dirHandle, byte* path, uint length, byte* type, ulong* size);
```

Dazu `internal static int WasmPackagePaths.List(string root, string relative, out (string Name, bool Directory)[] entries)`: Einträge nach
`StringComparison.Ordinal` sortiert, ohne `.`/`..` und ReparsePoints. Das Pufferformat für `readdir` ist das von `/save` (`WasiDirectoryEntries`,
`WasmSaveStore.cs:22`) und wird wiederverwendet. Ordner-Handles zählen gegen dieselbe Grenze wie Dateien (`ZEHOS_HOST_MAXIMUM_FILES` = 16, `zehos_host_core.h:24`).
